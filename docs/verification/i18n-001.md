# I18N-001 verification (.NET)

## Scope and design

Native ASP.NET Core request localization supports `en`/`es` with English as the
base/default/fallback. Only Accept-Language selects culture; regional parent
fallback and quality negotiation remain framework-owned. Core resources now live
in the ASP.NET Core adapter assembly. Security owns Identity descriptions through
the native IdentityErrorDescriber extension; Catalog/AiAgent own validation text
through narrow structured domain failures and their native HTTP exception handlers.
No translation wrapper, framework, plugin discovery or additional NuGet package
was introduced. See [runtime internationalization](../i18n.md).

Existing status, codes, technical fields, permissions, type URLs, JSON shapes,
normalization, password policy and business validation predicates are preserved.
Only existing human text is localized or becomes a complete parameterized phrase.
The shared v0.5.0 closed errors remain code-only and language independent. Runtime
OpenAPI retains one schema; multilingual API documentation is out of scope.
